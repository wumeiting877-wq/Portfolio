## 1. 权限体系现状（禁止重做）

四类角色已冻结，没有第五种角色，也没有按页面拆开的权限表。

| Role | `DataScope` | `PermissionAction` |
| --- | --- | --- |
| ADMIN | `GLOBAL` | read / create / update / delete |
| BOSS | `GLOBAL` | read |
| PROJECT_MANAGER | `MANAGED_PROJECTS` | read |
| MEMBER | `MEMBER_PROJECTS` | read |

定义位置：

- `ROLE_SCOPES`：`backend/app/permissions/scopes.py`
- `ROLE_PERMISSIONS`：`backend/app/permissions/roles.py`
- 写接口统一走 `require_admin` 或 `require_permission`；老板只读接口走 `require_admin_or_boss`

JWT 只携带身份，不作为授权真源。

- 签发：`issue_token()`，payload 为 `user_id`、`username`、`role`、`scope`、`exp`
- 每次请求：`get_current_user()` 用 token 里的 `user_id` 读库，角色取 `user.role.code`，Scope 用 `scope_for_role()` 重算
- 停用账号返回 401
- 前端把 `access_token` 放在 `localStorage`，角色判断使用 `/api/auth/me` 的 `profile.role`，不在前端解码 JWT 做授权

`GET /api/auth/me` 返回：`id`、`username`、`role`、`role_name`、`scope`、`status`、`must_change_password`、`employee_id`、`employee_name`。

前端 `useUserStore.displayName` 优先 `employee_name`，否则 `username`。页头在显示名与角色名不同时追加角色名。角色中文标签写死在 AdminLayout：管理员 / 老板 / 负责人 / 成员。

## 2. 登录后进入哪个页面

四类角色登录后的落点相同。

| 条件 | 目标 |
| --- | --- |
| 登录成功，且 `must_change_password = false` | route `home`，路径 `/`，组件 `HomeView` |
| 登录成功，且 `must_change_password = true` | route `change-password`，路径 `/change-password` |
| 已登录再打开 `/login` | 重定向到 `home` |
| 无 token | `/login` |
| token 失效或拉 profile 失败 | 清 token，回 `/login` |
| 必须改密时访问其他页 | 强制 `change-password` |
| `meta.roles` 不包含当前角色 | 重定向到 `home`，没有 403 页 |

实现：`LoginView.vue` 在登录后 `router.push`；`router.beforeEach` 做守卫。没有按角色选择首页。

页面名称不一致，四类角色都一样：

| 表面 | 文案 |
| --- | --- |
| 路由 `meta.title` / Breadcrumb | 首页 |
| `PageHeader` | 工作台 |
| 菜单项 | 首页 |

### 3.3 四类角色能打开的 Route

「能打开」指前端守卫放行。列表和详情里的行仍受后端 Scope 约束。

**ADMIN**

全部上表路由。写按钮可见。系统设置可保存。导入页可见。

**BOSS**

除 `/users` 外的全部业务路由。写按钮隐藏。系统设置只读。导入页隐藏，只保留其角色允许的导出项。直接请求写接口由后端 403。

**PROJECT_MANAGER**

守卫打回首页：`/recurring-expenses`、`/employees`、`/users`、`/audit-logs`、`/settings`。

**MEMBER**

与 PROJECT_MANAGER 相同的一套路由。首页和统计分析少排行区块。导出类型更少。`/api/statistics/project-costs` 与 `/api/statistics/employee-costs` 对 MEMBER 返回 403。

## 4. Backend Scope（当前真实范围）

无 `employee_id` 的 PROJECT_MANAGER / MEMBER：项目、资源、费用查询都是空集（`false()`），不是全局数据。

### 4.1 Project Scope

`readable_projects()`：

| 角色 | 可见项目 |
| --- | --- |
| ADMIN、BOSS | 全部项目 |
| PROJECT_MANAGER | `Project.manager_employee_id == 当前 employee_id` |
| MEMBER | 自己在 `project_members` 且 `is_active = true` 的项目 |

不可见项目的详情、成员接口返回「项目不存在」（404），不返回 403 泄露存在性。

写操作（创建、更新、归档、改项目编码、增删改成员）仅 ADMIN。

### 4.2 Resource Scope

`readable_resources()` / `readable_allocations()`：

| 角色 | 可见资源 |
| --- | --- |
| ADMIN、BOSS | 全部资源账号；分配搜索 `GET /api/resource-allocations` 仅 ADMIN、BOSS |
| PROJECT_MANAGER | 有效分配落在其负责项目上的资源；分配行限于这些项目 |
| MEMBER | 有效分配的 `employee_id` 为本人，且 `project_id` 为空或属于其参与项目 |

写操作（资源、类型、分配、停用、启用、稳定标识修正）仅 ADMIN。资源序列化不含口令或密钥字段。

### 4.3 Expense Scope

`readable_expenses()` / `readable_distributions()`：

| 角色 | 可见费用 |
| --- | --- |
| ADMIN、BOSS | 全部费用记录与分摊 |
| PROJECT_MANAGER | 分摊 `project_id` 落在其负责项目上的费用；分摊行也只保留这些项目 |
| MEMBER | 分摊 `employee_id` 为本人的费用记录与分摊行 |

统计金额一律从 `readable_distributions()` 出发，并且只计 `ExpenseRecord.status = ACTIVE`。按币种分组，不做跨币种相加。

可选 `project_id` / `employee_id` 是在已 Scope 的查询上再过滤。传入范围外的 id 得到空结果，不会扩大可见集。

写操作（费用、作废、建议分摊、周期生成、费用类型、周期规则的创建与启停）仅 ADMIN。周期规则的读取仅 ADMIN、BOSS，不走 Project/Expense Scope，因为 PROJECT_MANAGER 与 MEMBER 进不了该接口。

### 4.4 Notification Scope

列表、已读、解决：先过 `readable_notifications()`。

| 角色 | 可见提醒 |
| --- | --- |
| ADMIN、BOSS | 全部提醒，含无资源关联的周期规则提醒 |
| PROJECT_MANAGER、MEMBER | `resource_account_id` 落在 `readable_resources()` 内的提醒 |

`POST /api/notifications/refresh` 任何已登录角色都可调用。生成扫描的是全库资源与到期周期规则，生成后再按 Scope 返回列表。这是已有行为，R1 不重建提醒服务。

### 4.5 其他已有门禁

| 能力 | 读取 | 写入 |
| --- | --- | --- |
| 人员 | ADMIN、BOSS | ADMIN |
| 系统账号 / 角色列表 | ADMIN | ADMIN |
| 审计日志 | ADMIN、BOSS | — |
| 系统设置 | ADMIN、BOSS | ADMIN |
| 导入 | — | ADMIN |
| 导出 | 按类型见下表，且导出行走对应 Scope | — |
| 健康检查 `/health`、`/health/db` | 无登录要求；首页四类角色都展示 | — |

导出类型与后端 `EXPORT_TYPES`、前端 `frontend/src/api/exports.ts` 一致：

| 导出类型 | 允许角色 |
| --- | --- |
| employees、audit_logs | ADMIN |
| resource_type_costs、idle_resources | ADMIN、BOSS |
| projects、project_costs、employee_costs | ADMIN、BOSS、PROJECT_MANAGER |
| project_members、resource_allocations、expense_distributions | ADMIN、PROJECT_MANAGER |
| resources、expenses、expiring_resources | 四类角色 |

前端 `canExport` 只表示「已登录」，真正可选类型由上面的角色列表再滤一次。

## 5. Dashboard 当前返回哪些数据

首页和统计分析都调用同一组 Statistics API，没有第二套汇总。图表组件是现有 `IbmChart`（SVG）、`KpiStrip`、`MoneyText`、`StatusTag`、`PageHeader`。

Statistics API（全部要求登录，金额与资源计数都带 Scope）：

| 方法 | 路径 | MEMBER |
| --- | --- | --- |
| GET | `/api/statistics/overview` | 允许；响应字段换成「我的」计数 |
| GET | `/api/statistics/expense-trend` | 允许，范围为本人分摊 |
| GET | `/api/statistics/resource-type-costs` | 允许 |
| GET | `/api/statistics/billing-costs` | 允许；首页不调用，统计分析页会调用 |
| GET | `/api/statistics/resource-status` | 允许，资源范围为本人 |
| GET | `/api/statistics/expiring-resources` | 允许 |
| GET | `/api/statistics/project-costs` | 403「没有权限」 |
| GET | `/api/statistics/employee-costs` | 403「没有权限」 |

`overview` 对非 MEMBER 返回：`amounts_by_currency`、`project_count`、`employee_count`、`resource_count`、`active_resource_count`、`idle_resource_count`、`unassigned_active_resource_count`、`expired_resource_count`、`expiring_soon_count`。

`overview` 对 MEMBER 只返回：`amounts_by_currency`、`my_project_count`、`my_resource_count`、`my_expiring_resource_count`。`response_model_exclude_none=True`，其余计数字段不出现。

### 5.1 首页 `HomeView` 实际请求

四类角色共同请求：overview、expense-trend、resource-type-costs（limit 5）、resource-status、expiring-resources（days 30）。另外无条件请求 `/health` 与 `/health/db`。

| 角色 | 额外请求 | 页面上实际画出的块 |
| --- | --- | --- |
| ADMIN | project-costs limit 5 | 本期费用、项目数、活跃资源、闲置/未分配、即将到期；费用趋势；资源状态；项目费用 Top 5；资源类型费用 Top 5；即将到期；闲置；未分配但仍使用中 |
| BOSS | 与 ADMIN 相同 | 与 ADMIN 相同，无写按钮 |
| PROJECT_MANAGER | `listProjects`，以及 project-costs、employee-costs | 同上 KPI；负责项目多于 1 个时出现项目筛选；标题改为「我的项目费用」；另有项目成员费用和项目公共费用 |
| MEMBER | 无排行请求 | 我的本期费用、我参与的项目、我的资源、即将到期；费用趋势；资源状态；我的资源类型费用；即将到期资源。不画项目排行、成员排行、闲置、未分配 |

首页不请求 billing-costs，也不给 ADMIN/BOSS 画成员费用。成员费用只在 PROJECT_MANAGER 首页和统计分析「成员」Tab 出现。

下钻已存在，继续复用：

- 项目名 → `/projects/:id?tab=expenses`
- 资源名 → `/resources/:id?tab=expenses`
- 成员名 → `/expenses?employee_id=`

| R1 | 四角色登录后都进同一个「工作台」；PM 与 MEMBER 菜单相同；业务路由大多没有 `meta.roles`；Breadcrumb 一律从「首页」开始；页头「工作台」与路由「首页」不一致 | 在现有 Router + AdminLayout + Breadcrumb 上按角色组织入口、菜单、页面名、Breadcrumb、路由放行。数据请求继续打现有 API |
| R2 | BOSS 没有单独的经营总览壳。经营数字已在首页和统计分析里，和 ADMIN 挤在同一页 | 用现有 overview、trend、project-costs、employee-costs、billing-costs、resource-status 组成老板只读总览。不新写汇总 SQL |
