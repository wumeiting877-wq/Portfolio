# 企业项目资源与费用管理系统 V1.0 方案

## 1. 项目名称

**企业项目资源与费用管理系统**

可选简称：

- Project Cost Hub
- 企业资源费用台账
- 项目账号与成本管理平台

---

## 2. 项目定位

本项目用于统一管理企业内部：

- 项目
- 项目负责人
- 项目成员
- 系统登录账号
- 企业采购的资源账号
- 资源账号分配关系
- 项目费用
- 成员费用
- 各类一次性及周期性成本

核心目标：

> 清楚知道“哪个项目有哪些人、哪些人在使用哪些企业资源、这些资源花了多少钱、费用最终归属到哪个项目和成员”。

系统不定位为 ERP、OA、任务管理或财务记账系统。

第一阶段只聚焦：

**项目 + 人员 + 账号 + 资源 + 费用 + 权限 + 统计**

---

# 3. 核心业务对象

系统中必须明确区分两类“账号”。

## 3.1 系统登录账号

用于登录本管理系统。

角色包括：

1. 老板
2. 项目负责人
3. 普通项目成员
4. 管理员

系统不开放自主注册。

所有系统登录账号统一由管理员创建。

管理员负责：

- 创建登录账号
- 设置用户名
- 设置初始密码
- 分配角色
- 绑定人员
- 启用账号
- 停用账号
- 重置密码

用户首次登录后可允许修改自己的密码。

---

## 3.2 企业资源账号

企业采购后分配给员工或项目使用的外部资源。

例如：

- ChatGPT
- Cursor
- Claude
- GitHub
- Figma
- Microsoft 365
- 企业邮箱
- 云服务器
- API Key
- 数据库服务
- 域名
- OSS
- SaaS 系统
- 其他软件账号

资源账号主要用于回答：

- 谁在使用？
- 属于哪个项目？
- 哪种类型？
- 什么套餐？
- 是否共享？
- 从什么时候开始使用？
- 当前状态是什么？
- 每月多少钱？
- 是否有一次性费用？
- 是否存在 API 按量费用？
- 一共花费了多少钱？

---

# 4. 用户角色与权限

## 4.1 老板

角色定位：

**全局只读领导账号。**

权限范围：

- 查看全部项目
- 查看全部负责人
- 查看全部成员
- 查看全部资源账号
- 查看全部费用
- 查看全部项目费用
- 查看全部成员费用
- 查看全部资源类型费用
- 查看费用趋势
- 查看资源使用率
- 查看闲置资源
- 查看即将到期资源
- 导出数据

禁止：

- 新增
- 修改
- 删除
- 分配资源
- 调整费用
- 修改人员
- 修改项目

老板账号只负责查看和决策。

---

## 4.2 项目负责人

角色定位：

**项目级只读领导账号。**

可查看：

- 自己负责的项目
- 自己项目的成员
- 自己项目的资源账号
- 自己项目的费用
- 项目成员资源使用情况
- 项目费用趋势
- 项目费用类型分布
- 项目月度费用
- 项目费用明细
- 自己项目的导出数据

禁止：

- 查看其他项目
- 修改项目
- 添加成员
- 删除成员
- 分配资源账号
- 修改费用
- 删除费用

---

## 4.3 普通项目成员

普通成员可以登录系统。

数据范围：

**只能查看自己参与的项目。**

如果成员同时参与多个项目，则可以查看自己参与的全部项目。

可查看：

- 项目基础信息
- 项目负责人
- 项目成员
- 自己参与项目的资源情况
- 自己使用的资源账号
- 自己相关费用
- 项目级公开费用数据

建议第一版：

普通成员默认只能看到：

- 自己使用的资源
- 自己相关费用
- 项目总体费用

不直接显示其他成员的详细个人费用。

后续可通过权限配置开放。

禁止：

- 新增
- 修改
- 删除
- 分配资源
- 修改费用
- 修改项目
- 修改成员

---

## 4.4 管理员

角色定位：

**系统唯一可维护业务数据的角色。**

管理员可以：

- 创建项目
- 修改项目
- 项目归档
- 设置项目负责人
- 添加项目成员
- 移除项目成员
- 创建系统账号
- 设置角色
- 重置密码
- 停用系统账号
- 创建资源账号
- 修改资源账号
- 分配资源账号
- 调整资源账号使用人
- 设置资源所属项目
- 设置共享账号
- 新增费用
- 修改费用
- 删除错误费用
- 管理资源类型
- 管理费用类型
- 导入数据
- 导出数据

# 6. 项目管理

## 6.1 项目基础字段

每个项目至少包含：

- 项目 ID
- 项目名称
- 项目编码
- 项目负责人
- 项目成员
- 项目状态
- 开始时间
- 结束时间
- 项目说明
- 创建人
- 创建时间
- 更新时间

项目状态：

- 筹备中
- 进行中
- 已暂停
- 已完成
- 已归档

---

## 6.2 项目与人员关系

支持：

- 一个项目有一个主要负责人
- 一个项目有多个成员
- 一个成员可以加入多个项目
- 一个负责人也可以同时负责多个项目

系统必须使用“项目成员关系表”维护，而不是直接把项目 ID 写死到人员表。

---

# 7. 人员管理

人员基础字段：

- 姓名
- 工号
- 部门
- 职位
- 联系方式
- 邮箱
- 在职状态
- 是否拥有系统登录账号
- 备注

人员状态：

- 在职
- 离职
- 停用

人员和系统登录账号必须分离。

即：

> 一个人可以存在于人员表中，但未必一定拥有登录账号。

---

# 8. 系统账号管理

系统账号字段：

- 用户名
- 登录密码
- 绑定人员
- 系统角色
- 账号状态
- 最近登录时间
- 创建时间
- 密码更新时间

状态：

- 正常
- 已停用
- 已锁定

要求：

- 禁止开放注册
- 管理员创建账号
- 管理员分配角色
- 管理员设置初始密码
- 密码不得明文存储
- 使用强哈希算法
- 建议使用 Argon2 或 bcrypt
- JWT 登录鉴权
- 所有接口必须后端校验权限

---

# 10. 共享资源账号

系统必须支持：

**一个资源账号分配给多个人使用。**

例如：

ChatGPT Team Account A：

- 张三
- 李四
- 王五

共享账号不能只使用单一 user_id。

必须使用独立的：

**resource_allocations 资源分配关系表**

记录：

- 资源账号
- 使用人
- 所属项目
- 分配开始时间
- 分配结束时间
- 当前是否有效

这样可以追踪历史。

---

# 11. 资源凭据安全

第一版不建议直接保存外部资源的明文密码。

建议资源账号中只保存：

- 平台
- 登录邮箱
- 账号名称
- 使用人员
- 套餐
- 费用
- 状态

如果后期必须保存外部账号密码/API Key：

必须新增独立的凭据管理模块。

要求：

- 数据库加密
- 前端默认脱敏
- 权限独立
- 查看操作记录审计日志
- 密钥不能写入普通业务日志

---

# 13. 费用记录字段

每条费用至少包含：

- 费用 ID
- 项目
- 成员
- 资源账号
- 费用类型
- 费用子类型
- 金额
- 币种
- 费用日期
- 费用月份
- 计费方式
- 是否周期费用
- 费用说明
- 创建人
- 创建时间
- 更新时间

其中：

项目、成员、资源账号允许部分为空。

例如：

公司级服务器费用可以只关联项目，不关联个人。

---

# 14. 费用归属规则

系统必须允许：

## 模式 A：归属项目

例如：

服务器费用 ¥1000

全部计入：

新华制药项目。

---

## 模式 B：归属成员

例如：

Cursor Pro ¥140

归属：

李四。

---

## 模式 C：同时归属项目和成员

例如：

李四使用 Cursor Pro。

记录：

- 项目：新华制药
- 人员：李四
- 资源：Cursor-Pro-01
- 金额：¥140

---

## 模式 D：共享费用

例如：

ChatGPT Team ¥1000

多人使用。

第一版可直接将全部费用计入所属项目。

后续版本增加：

- 平均分摊
- 按比例分摊
- 自定义分摊

---

# 15. 自动周期费用

为避免管理员每个月重复录入订阅费用，建议支持自动生成费用记录。

例如：

Cursor：

- ¥140/月
- 开始：2026-09-01
- 状态：使用中

系统自动产生：

- 2026-09 ¥140
- 2026-10 ¥140
- 2026-11 ¥140

管理员可以修正实际金额。

自动生成规则必须保留来源字段：

- AUTO
- MANUAL
- IMPORT

# 20. Excel 导入

第一版建议至少支持：

- 人员导入
- 项目导入
- 资源账号导入
- 费用记录导入

必须提供标准 Excel 模板。

导入流程：

上传文件
→ 字段检查
→ 数据预览
→ 错误提示
→ 确认导入
→ 返回结果

禁止错误数据直接静默写入数据库。

---

# 21. 审计日志

管理员可以修改费用和资源，因此必须保留审计日志。

记录：

- 操作人
- 操作类型
- 业务模块
- 业务数据 ID
- 修改前
- 修改后
- 操作时间
- IP
- 备注

典型日志：

`管理员 admin 修改资源 Cursor-01 使用人：李四 → 王五`

`管理员 admin 修改费用：140 → 160`

领导账号不允许删除审计日志。

# 23. 核心数据库关系

```text
Employee
   │
   ├──────── User
   │
   └──────── ProjectMember
                  │
                  ▼
               Project
                  │
        ┌─────────┴─────────┐
        ▼                   ▼
ResourceAccount         ExpenseRecord
        │
        ▼
ResourceAllocation
        │
        ▼
     Employee
```

核心原则：

- User 与 Employee 分离
- Project 与 Employee 多对多
- Resource 与 Employee 多对多
- Expense 可关联 Project / Employee / Resource

# 27. 权限实现原则

不能只依赖前端隐藏按钮。

必须：

## 前端

控制：

- 菜单
- 页面
- 按钮

## 后端

再次验证：

- 当前角色
- 当前用户
- 项目数据范围
- 是否拥有修改权限

例如：

负责人请求：

`GET /api/projects/100`

后端必须验证：

该项目是否由当前负责人负责。

不能只通过 URL 或前端进行控制。

# 33. 项目成功标准

V1.0 上线后，应能够在 1 分钟内回答以下问题：

### 老板

- 这个月公司总共花了多少钱？
- 哪个项目花费最高？
- 哪个人花费最高？
- AI 工具一共花了多少钱？
- Cursor 一共多少账号？
- 哪些账号没人使用？
- 哪些账号快到期？
- 某个成员正在使用什么资源？

### 项目负责人

- 我的项目这个月花了多少？
- 哪些成员正在使用资源？
- 我的项目 Cursor 花了多少？
- 项目费用最近是否上涨？

### 普通成员

- 我在哪些项目？
- 我正在使用哪些账号？
- 我的资源什么时候到期？
- 我的相关费用是多少？

### 管理员

- 当前有哪些项目？
- 哪些账号待分配？
- 哪些资源要续费？
- 如何把某个资源调整给其他成员？
- 如何补录一次性/API/服务器费用？

# 36. 最终结论

本项目建议采用：

**完全独立、自研、轻量化方案。**

不引入 ERPNext、Odoo 等大型开源 ERP。

V1.0 核心只围绕：

> 项目  
> 人员  
> 系统账号  
> 企业资源账号  
> 资源分配  
> 费用  
> 权限  
> 统计  
> Excel  
> 审计

系统真正的核心竞争点不是功能数量，而是：

> **任何时候都能快速知道：谁，在什么项目，使用了什么企业资源，花了多少钱。**

这应该作为后续所有开发和设计的最高级业务原则。
